Add it to your agent.

The Sunday Letter ships as a Claude/Cowork plugin and a Codex-compatible plugin. Install once. Subscribe to a weekly slot, any weekday and time you like. Receive a letter only when something has actually changed.

Step 01 · Install the plugin

Pick how you run Claude.

Each path gives you the same contract: the sunday-letter skill, the shared schema, and the Archive renderer. Codex also includes a local seven-day history collector.

A

Cowork (desktop)

Download the .plugin bundle and drop it into your Cowork plugins folder.

↓  Download sunday-letter.plugin
B

Codex Desktop

Download the Codex bundle and import it as a local plugin. The Codex version can collect the last seven days of local Codex threads before writing.

↓  Download sunday-letter-codex.plugin

C

Claude Code (CLI)

Inside Claude Code, add the repo as a marketplace, then install.

>/plugin marketplace add selinayfilizp/sunday-letter
>/plugin install sunday-letter@sunday-letter
Step 02 · Subscribe

Tell your agent when to write.

Once installed, run /subscribe-sunday-letter in Claude. You'll pick a weekly slot: which day, which time, and optionally which timezone (IANA, e.g. Europe/Berlin). Run the command again anytime to reschedule.

Sunday at 6:00 PM The default story. Cron uses your scheduler's local clock unless you set a timezone on the task.
0 18 * * 0
Same day, different time Keep Sunday, move the hour, for example morning coffee before the week starts.
30 9 * * 0
Another weekday + time Monday debrief, Friday wind-down, Wednesday lunch, your rhythm, not ours.
30 19 * * 4
Just write one now Skip the schedule. Run /sunday-letter on demand.
manual

Build your cron line

Pick a day and time. Copy the five-field cron expression into your agent or scheduler. Format is minute hour * * dayOfWeek where 0 is Sunday and 6 is Saturday.

0 18 * * 0

Tell your agent your IANA timezone if it can set CRON_TZ or a per-task zone; otherwise choose the wall time that matches where the schedule runs. Example saved config: schedule-config.example.json (same file ships in the plugin under skills/sunday-letter/references/).

Step 03 · The contract

What you've signed up for.

Every letter obeys six rules. A letter that violates any of them does not ship.

  1. Consequences first. Open with what your agent actually did for you this week, drafts, filters, declines, shortlists.
  2. Epistemic honesty. No fake percentages. Observations are hedged in natural language: fairly sure, a guess, still checking.
  3. Provenance on everything. Each claim has a paraphrased quote from a real conversation, with a date.
  4. Default silence. If nothing meaningful changed, no letter ships. Skipped weeks are visible in the archive.
  5. Retire something. Monthly or more often, your agent crosses out a belief it used to hold about you and replaces it with what it holds now.
  6. One question. One generative, specific question, not a list, not a survey, not rhetoric.
