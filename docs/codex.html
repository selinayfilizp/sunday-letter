The Sunday Letter
Sample Install GitHub
Codex Desktop · local context collector

Make the letter read the actual week.

In Codex, the Sunday Letter is not just a prompt. It has a local collector that reads the last seven days of Codex Desktop threads, extracts decisions and open loops, then renders the same Archive-style letter used by Claude/Cowork.

The architecture

Shared contract One schema for consequences, decisions, open tasks, observations, retired beliefs, and the weekly question.
Host-specific collectors Codex reads local rollout files. Claude/Cowork uses its own conversation history or an exported transcript bundle.
One renderer The generated JSON renders through the same self-contained HTML template.
Default silence If nothing meaningful changed, the job skips instead of inventing a weekly note.

Install in Codex

Import the Codex-compatible bundle, or add the repo as a local plugin source.

Download sunday-letter-codex.plugin

python3 skills/sunday-letter/scripts/collect_codex_context.py \
  --days 7 \
  --out letters/codex-weekly-context.md \
  --limit 80 \
  --per-message-limit 3000

The collector reads local Codex state under ~/.codex. It does not upload transcripts anywhere.

What the weekly automation should do

  1. Run the Codex collector for the last seven days.
  2. Read the generated context bundle.
  3. Extract weekly signals into the Sunday Letter schema.
  4. Carry forward decisions and open tasks as first-class objects.
  5. Render the letter with generate_letter.py.
  6. Skip if there is no meaningful delta.

Claude/Cowork compatibility

The letter contract is portable. The collector is not. For Claude/Cowork, use the host's conversation-history tool or export a transcript bundle into the same shape Codex produces. The renderer and schema stay the same.

collector output -> weekly context markdown
weekly context -> signals JSON
signals JSON -> Archive HTML letter
